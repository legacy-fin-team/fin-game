# Квесты

Квест — короткая история, в которой ребёнок на каждом шаге выбирает один из 2–4 вариантов. Выбор
меняет монеты, шкалы питомца и прогресс квеста, а после него игра коротко объясняет, что получилось.
Здесь описаны формат данных, правила движка, ожидание и кулдауны, случайные квесты, проверка
взрослым, свои квесты взрослого и пример добавления нового квеста.

Пути к исходникам даны относительно `app/src/main/java/com/legacy/fingame/`, пути к данным —
относительно `app/src/main/assets/`.

Связанные разделы: [экономика и журнал](economy.md), [шкалы и рост питомца](pet-growth.md),
[образовательные темы](education.md), [варианты сборки](build.md).

## 1. Где что лежит

| Доступность и её причина | `game/quests/QuestAvailability.kt` |
| Темы финансовой грамотности | `game/quests/QuestTopic.kt` |
| Чтение `quests.xml` | `game/quests/QuestReader.kt`, `QuestRegistry.kt` |
| Список для экрана | `game/quests/QuestBoard.kt` |
| История выборов (до 200 записей) | `game/quests/QuestLog.kt` |
| Свои квесты взрослого | `game/quests/CustomQuests.kt` |
| Применение исходов к деньгам и питомцу | `game/GameViewModel.kt` → `startQuest`, `chooseQuestOption`, `advanceQuest`, `restartQuest`, `approveQuestCheck`, `rejectQuestCheck`, `enableQuest` |
| Экран | `ui/screens/QuestsScreen.kt`, тексты — `ui/screens/QuestFormat.kt` |

возвращает новое состояние или `null`, если действие сейчас невозможно.

## 2. Типы квестов

| Тип | `kind` | Как начинается |
|---|---|---|
| Квест игрока | `player` | Кнопкой «Взять» на экране квестов |
| Случайный | `random` | Сам, пока игрок играет (раздел 5) |

## 3. Формат `quests.xml`

```xml
<quest id="piggy_bank" title="Копилка" kind="player" start="gift" cooldown-minutes="180"
       image="quests/piggy_bank.webp" topic="saving">
    <description>Научись откладывать: терпение приносит монеты.</description>
    <node id="gift" delay-minutes="2">
        <text>Бабушка подарила монетки. Потратить сразу или отложить?</text>
        <option label="В копилку" next="wait">
            <result>Монетки звякнули в копилке. Подождём!</result>
        </option>
        <option label="На мороженое" next="end">
            <result>Вкусно! Но подарок уже съеден.</result>
            <effect stat="pleasure" value="10" />
            <effect stat="hunger" value="5" />
        </option>
    </node>
    …
</quest>
```

В колонке «По умолчанию»: «обязателен» — без этого атрибута или тега квест не читается; «не задан»
— атрибут можно не писать, и тогда у квеста этого свойства просто нет.

| Атрибут / тег | По умолчанию | Смысл |
|---|---|---|
| `id` | обязателен | Уникальный идентификатор |
| `title` | обязателен | Название |
| `kind` | обязателен | `player` или `random` |
| `start` | обязателен | `id` первого узла |
| `progress` | `false` | Есть ли у квеста шкала прогресса 0–100 |
| `min-balance` | 0 | Сколько монет нужно на счёте, чтобы взять квест; **не списывается** |
| `repeatable` | `true` | `false` — одноразовый: после прохождения закрыт, пока взрослый не нажмёт «Включить снова» |
| `cooldown-minutes` | 60 (`Quest.DEFAULT_COOLDOWN_MINUTES`) | Сколько минут ждать после прохождения, прежде чем взять снова |
| `stage-delay-minutes` | 0 | Пауза между шагами для узлов без своего `delay-minutes` |
| `requires-adult-check` | `false` | Каждый выбор проверяет взрослый (раздел 7) |
| `topic` | не задан | Тема: `planning`, `needs-wants`, `saving`, `deposit`, `goals`, `honesty` (см. [education.md](education.md)) |
| `image` | не задан | Картинка `assets/textures/<путь>`; если файла нет, показывается иконка квестов |
| `<description>` | пусто | Описание на карточке |
| `<node id delay-minutes image>` | обязателен, хотя бы один | Шаг (ситуация); `delay-minutes` — через сколько минут после выбора откроется следующий шаг, по умолчанию `stage-delay-minutes` |
| `<text>` | обязателен | Текст ситуации |
| `<option label next money progress>` | обязателен, хотя бы один; `money` 0, `progress` 0 | Вариант: надпись на кнопке (до 16 символов — это проверяют `ShippedQuestsTest` и форма своих квестов, `QuestReader` длину не ограничивает), следующий узел или `end`, изменение монет и прогресса |
| `<result>` | обязателен | Что получилось после выбора |
| `<effect stat value>` | не задан | Изменение шкалы `health`, `hunger`, `pleasure` |

`QuestReader` отбрасывает квест целиком при ошибке в нём (нет `id`/`title`/`start`, неизвестный
`kind` или `topic`, отрицательные задержки, нет узлов, ссылка на несуществующий узел, у варианта нет
надписи, `<result>` или `next`) и пишет причину в logcat. Остальные квесты читаются.

## 4. Правила

| Правило | Как работает | Где |
|---|---|---|
| Можно ли взять | квест не идёт сейчас; одноразовый ещё не пройден (или включён снова); кулдаун истёк; `balance ≥ min-balance` | `QuestEngine.availabilityOf` |
| Причина «нельзя» | `ACTIVE`, `ONE_TIME_DONE`, `COOLDOWN` (с моментом, когда станет можно), `NOT_ENOUGH_MONEY` | `QuestUnavailableReason` |
| Кулдаун | `конец кулдауна = момент прохождения + cooldown-minutes`; на карточке отсчёт «Доступен через 1:02:03» или «Доступен через 0:42» (`QuestFormat.countdownText`) | `availabilityOf` |
| Вариант с тратой | доступен, только если `−money ≤ balance` | `QuestEngine.canAfford` |
| Деньги | `balance' = max(0, balance + money)`; трата дополнительно урезается до текущего баланса; строка журнала «Квест: <название>» | `QuestEngine.choose`, `GameViewModel.applyQuestEffects` |
| Шкалы питомца | `шкала' = clamp(шкала + effect, 0, 100)` для каждого `<effect>` | `PetStats.changedBy` |
| Прогресс (если `progress="true"`) | `progress' = clamp(progress + Δ, 0, 100)` | `QuestEngine.choose` |
| Пауза после выбора | `следующий шаг доступен = момент выбора + delay-minutes узла`; после последнего варианта ждать нечего | `QuestEngine.choose`, `advance` |
| Шаг, пропавший из данных | квест завершается, а не висит активным | `QuestEngine.advance`, восстановление в `GameViewModel` |
| Точка на кнопке квестов | горит, если у идущего квеста открылся шаг после последнего взгляда на экран | `QuestEngine.hasUnseenStep` |

В формулах `clamp(x, a, b)` означает «x, но не меньше a и не больше b».

Деньги квестов не входят в план бюджета: это не трата и не доход периода (см.
[economy.md](economy.md)). Эффекты квестов меняют шкалы, но не засчитываются как забота за день
(см. [pet-growth.md](pet-growth.md), раздел 3).

Все время квестов считается по часам игры (`GameViewModel.nowMillis`), поэтому перемотка «+12 ч» в
демо-сборке сдвигает и кулдауны, и паузы.

## 5. Случайные квесты

Проверка идёт в каждом `tick()` (раз в 30 секунд, пока приложение открыто и питомец выбран) —
`QuestEngine.maybeSpawnRandom`:

1. если уже идёт случайный квест — ничего;
2. с последнего случайного квеста (а если их не было — с момента, когда взяли питомца) должно пройти
   не меньше 6 часов (`RANDOM_QUEST_COOLDOWN_MILLIS`);
3. кандидаты — случайные квесты, которые можно начать (кулдаун, одноразовость, минимум монет);
4. бросок: выпадает с вероятностью 1/4 (`RANDOM_QUEST_CHANCE = 4`), квест выбирается равновероятно.

Без выбранного питомца квесты не выпадают.

## 6. Ожидание и демо-сборка

Кулдауны, паузы между шагами и шесть часов между случайными квестами действуют во всех сборках —
debug, release и releaseDebuggable. `MainActivity` создаёт `GameViewModel` с
`ignoreQuestDelays = false`; сам флаг остался только для тестов, а ядро `QuestEngine` о сборке
ничего не знает.

Чтобы показать квест без ожидания, в демо-сборке (`DemoMode.ENABLED`, по умолчанию — debug, для
любой сборки — `-Pfingame.demoMode=true`, см. [build.md](build.md)) есть две кнопки:

| Кнопка | Где | Что делает |
|---|---|---|
| «+12 ч» | Главный экран | Сдвигает часы игры на 12 часов вперёд. Все ожидания квестов считаются по этим часам, поэтому одно нажатие снимает паузу или кулдаун до 12 часов, два — сутки (паузу между днями «Пикника») |
| «Ещё раз» | Карточка пройденного квеста игрока | Начинает квест заново (`GameViewModel.restartQuest`) по тем же правилам, что и «Взять», в том числе с кулдауном |

Проверка взрослым действует во всех сборках.

## 7. Проверка взрослым

У квеста с `requires-adult-check="true"` (у своих квестов — «Проверяю я»):

1. выбор ребёнка переводит шаг в `QuestCheck.WAITING`; ребёнок видит «Ждём, пока взрослый проверит»,
   награды нет (`QuestEngine.choose` возвращает `awaitingCheck = true`); в истории — `SENT`;
2. взрослый в режиме взрослого, вкладка «Квесты» → «На проверку»:
   - «Засчитать» (`approve`) — начисляются деньги (трата урезается до текущего баланса), эффекты и
     прогресс, запускается пауза шага; в истории — `APPROVED`;
   - «Не засчитано» (`reject`) — шаг возвращается в работу, ребёнок видит «Взрослый пока не засчитал
     этот шаг. Попробуй ещё раз!»; в истории — `REJECTED`;
3. проверка идёт на каждом шаге и не зависит от сборки.

## 8. Свои квесты взрослого

Вкладка «Квесты» взрослого → «Свои квесты»: форма в несколько страниц («Основное», «Правила»,
«Ситуация N из M», «Проверка»). Квест собирается `CustomQuestDraft.toQuest`: квест игрока, линейная
цепочка шагов `s1 → s2 → s3 → end`, `id` — `custom-<момент>`.

| Поле | Пределы (`CustomQuests`) |
|---|---|
| Число своих квестов | до 20 |
| Название / описание | до 24 / до 120 символов |
| Минимум монет, чтобы взять | 0–999 |
| Шагов (ситуаций) | 1–3, текст ситуации до 120 символов |
| Вариантов в шаге | 2–3; надпись до 16, результат до 80 символов |
| Монеты за вариант | −100…+100, шаг 10 |
| Шкалы «Сытость», «Здоровье», «Настроение» | −20…+20, шаг 5 |
| Прогресс за вариант | 0, 25, 50 или 100 % |
| «Многоразовый / Одноразовый» | по умолчанию многоразовый |
| «Кулдаун, мин» | 0–10 080 (неделя), по умолчанию 60; 0 — без кулдауна |
| «Пауза между этапами, мин» | 0–1 440 (сутки), по умолчанию 0; одна на весь квест |
| «Сам / Проверяю я» | проверка взрослым |
| «Тема» | одна из шести или «Без темы» |

- **Изменить** можно только свой квест. Если ребёнок его сейчас проходит, форма предупреждает:
  «После сохранения прохождение начнётся заново: прогресс сбросится, полученные монеты останутся»
  (`GameViewModel.updateCustomQuest` удаляет идущее прохождение).
- **Убрать** — с подтверждением «Убрать «…»?»; идущее прохождение прерывается, выборы остаются в
  истории.
- **Включить снова** — у пройденного одноразового квеста (и у любого пройденного — снимает кулдаун
  на один раз): `QuestEngine.enable`, флаг `QuestProgress.enabledAgain`.
- Свои квесты хранятся в `PlayerState.customQuests` и переживают сброс прогресса.

## 9. Встроенные квесты

Шесть квестов в `assets/data/quests.xml`: три квеста игрока и три случайных. Все многоразовые, у
всех есть тема; картинок `quests/<id>.webp` пока нет — на карточках иконка квестов.

| Квест | `id` | Тип | Условия и ожидание | Шаги и деньги по вариантам | Тема |
|---|---|---|---|---|---|
| Пикник | `picnic` | игрока, с прогрессом | от 300 монет на счёте; кулдаун 60 мин; пауза 24 ч после 1-го и 2-го дня | 16 шагов за 3 дня, от −90 до +150 за шаг (ниже) | `planning` |
| Копилка | `piggy_bank` | игрока | от 0 монет; кулдаун 180 мин; пауза 2 мин после 1-го шага | «В копилку» → «Открыть» +20 или «Копить дальше» +40; «На мороженое» 0 | `saving` |
| Лимонад | `lemonade` | игрока, с прогрессом | от 50 монет; кулдаун 120 мин; пауза 1 мин после 1-го шага | рецепт: свежие лимоны −30 / сок −15 / вода 0; цена за стакан: честная +50 / низкая +35 / завышенная +20 | `saving` |
| Потерянный кошелёк | `lost_wallet` | случайный | кулдаун 60 мин; без пауз | «Вернуть» +20 (настроение +15) / «Оставить себе» +30 (настроение −20) | `honesty` |
| Гости | `guests` | случайный, с прогрессом | кулдаун 60 мин; пауза 2 мин после 1-го шага | угощение: испечь −10 / торт −30 / чай 0; уборка: прибраться 0 / «И так сойдёт» 0 | `needs-wants` |
| Ярмарка | `fair` | случайный | кулдаун 120 мин; пауза 1 мин после 1-го шага | «К аттракционам» −20 → перекус −10 / вода 0; «Смотреть фокусы» 0; «Помочь с уборкой» +25 | `needs-wants` |

### «Пикник» по дням

Самый длинный квест: подготовка, поездка и возвращение растянуты на три игровых дня. Отдельного
атрибута «день» в формате нет — дни разделены паузой `delay-minutes="1440"` (24 часа) на последнем
шаге первого и второго дня, а «День 2», «День 3» написаны в тексте шагов.

| День | Шаги | О чём выбор | Деньги |
|---|---|---|---|
| 1 | `store`, `food_set`, `home_items`, `extra_items`, `transport` | Где купить продукты, какой набор взять, что взять из дома, что докупить, на чём ехать | гипермаркет 0 / рынок −50 / доставка −80; овощи 0 / шашлык −40 / деликатесы −90; из дома 0; палатка −60 / посуда −20 / игрушка −30 / ничего 0; электричка −10 / такси −70 / пешком 0 |
| 2 | `quiz_1` … `quiz_5`, `activity` | Пять вопросов старичка о деньгах (один верный ответ из трёх), затем чем заняться | верный ответ +10, неверный 0 (настроение −5 или −10); футбол −20 / катамаран −30 / рыбалка −15 / прогулка 0 |
| 3 | `cleanup`, `split_bill`, `return_transport`, `receipt_check`, `claim_reward` | Убрать мусор, поделить счёт с друзьями, дорога домой, найти лишнюю покупку в чеке, забрать награду | мусор: собрать 0 / оставить −50 / сжечь −25 (штраф); счёт: заплатить за всех 0 / поровну +50 / поругаться 0; дорога как в день 1; чек: верно +5, неверно −10; награда +150 |

Прогресс начисляется почти за каждый шаг: лучшие варианты дают ровно 100 %. Почти у всех вариантов
есть и эффект на шкалы — например, «Шкаф» из дома или брошенный мусор портят настроение на 15.

## 10. Пример: как добавить новый квест

Добавим квест игрока «Выпечка» на тему «Накопление».

1. **Данные.** В конец `<quests>` в `app/src/main/assets/data/quests.xml`:

   ```xml
   <quest id="bakery" title="Выпечка" kind="player" progress="true" min-balance="20"
          start="stand" image="quests/bakery.webp" topic="saving">
       <description>Испеки печенье на продажу и реши, что делать с выручкой.</description>
       <node id="stand" delay-minutes="5">
           <text>Нужны мука и масло. Купить хорошие или подешевле?</text>
           <option label="Хорошие" next="money" money="-20" progress="50">
               <result>Печенье вкусное — очередь до угла!</result>
               <effect stat="pleasure" value="10" />
           </option>
           <option label="Подешевле" next="money" money="-10" progress="20">
               <result>Суховато вышло, покупателей мало.</result>
           </option>
           <option label="Из запасов" next="money" progress="30">
               <result>Дома нашлась мука — бесплатно, но её мало.</result>
           </option>
       </node>
       <node id="money">
           <text>Выручка — 40 монет. Что с ними сделать?</text>
           <option label="Отложить" next="end" money="40" progress="50">
               <result>Монеты в копилке — на цель стало ближе.</result>
           </option>
           <option label="Потратить" next="end" money="40">
               <result>Потратил сразу. Приятно, но ненадолго.</result>
               <effect stat="pleasure" value="5" />
           </option>
       </node>
   </quest>
   ```

   Правила, которые проверяет `ShippedQuestsTest` для каждого поставляемого квеста: в каждом шаге
   есть бесплатный вариант (`money ≥ 0`); все узлы достижимы из `start`; надписи на кнопках — до
   16 символов; у квеста с прогрессом лучшие варианты шагов дают в сумме ровно 100 % (здесь
   50 + 50); квест многоразовый с кулдауном не меньше 60 минут; `image="quests/<id>.webp"`.

2. **Картинка (необязательно).** `app/src/main/assets/textures/quests/bakery.webp`. Без неё
   показывается иконка квестов.

3. **Тесты.** `app/src/test/java/com/legacy/fingame/ShippedQuestsTest.kt` фиксирует список
   поставляемых квестов и их темы — добавить `bakery`:

   ```kotlin
   assertEquals(
       listOf("picnic", "piggy_bank", "lost_wallet", "guests", "lemonade", "fair", "bakery"),
       quests.map { it.id }
   )
   // и в `every shipped quest has a topic`:
   "bakery" to QuestTopic.SAVING
   ```

   Затем `./gradlew :app:testDebugUnitTest`.

4. **Проверка в игре.** Во всех сборках после первого шага квест ждёт 5 минут; в демо-сборке паузу
