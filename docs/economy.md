# Экономика: деньги, бюджет, вклад, журнал

Как игрок получает и тратит монеты, как устроены два счёта, план периода по категориям, вклад и
журнал. Числа баланса (стартовые деньги, бонус дня, ставки вкладов) здесь не фиксируются: они заданы
константами в коде, ссылки на них даны ниже.

Пути к исходникам даны относительно `app/src/main/java/com/legacy/fingame/`.

Связанные разделы: [штрафы за плохой уход](pet-growth.md), [магазин и цены](items.md),
[квесты](quests.md), [образовательный смысл](education.md).

## 2. Константы

| Параметр | Значение | Где |
|---|---|---|
| Стартовый баланс | задан константой | `Economy.STARTING_BALANCE` |
| Бонус дня | выдаётся раз в календарные сутки; размер задан константой; меньше при серии дней без заботы (см. [pet-growth.md](pet-growth.md)) | `Economy.DAILY_BONUS`, `GameUiState.dailyIncome` |
| Доступность бонуса | `сегодня > день последнего бонуса` (перевод часов назад бонус не даёт) | `Economy.isDailyBonusAvailable` |
| Сроки вклада | диапазон дней, границы — константы | `Deposit.MIN_TERM_DAYS`, `MAX_TERM_DAYS` |
| Журнал денег | до 500 записей, новые сверху | `MoneyLog.MAX_ENTRIES` |
| История периодов | до 60 итогов | `BudgetHistory.MAX` |
| Товар в корзине | еда — до 99; остальное — 1, если этот вариант ещё не куплен | `GameViewModel.MAX_ITEM_QUANTITY`, `maxQuantityOf` |
| Перемотка в демо-сборке | +12 ч за нажатие | `DemoMode.FAST_FORWARD_HOURS` |

«Сегодня» — календарный день устройства (`LocalDate.now().toEpochDay()`) плюс дни, пропущенные
перемоткой; день никогда не уменьшается (`FastForwardClock.today`).

## 3. Два счёта

- **Текущий счёт** (`PlayerState.balance`) — всё, что можно тратить. Сбережения — это часть текущего
  счёта, которую ребёнок решил не тратить; отдельного счёта «сбережения» нет (старый ключ `savings`
  при загрузке возвращается на баланс, см. [architecture.md](architecture.md)).
- **Вклад** (`PlayerState.deposit`) — деньги, отложенные на срок под процент. Открыт может быть
  только один вклад; в раскладку периода тело вклада не входит (`GameUiState.totalToPlan = balance`).

## 4. Бюджет периода

Период длится от одного бонуса дня до следующего.

1. **Бонус дня** (`claimDailyBonus`): сначала `tick()` (питомец и вклад догоняют часы), потом
   закрывается текущий период в `BudgetResult`, `balance += dailyIncome`, строка журнала «Бонус дня»,
   открывается планирование (`planningOpen = true`) и экран бюджета.
2. **Раскладка** (`BudgetDraft`: обязательные, необязательные, сумма и срок вклада) — ползунками и
   кнопками «−/+»; черновик сохраняется и переживает перезапуск (`updateBudgetDraft`). Раскладка всегда
   приводится к допустимой (`Budget.normalize`): каждая сумма уменьшается так, чтобы вместе они
   не превышали доступные деньги. В формулах `clamp(x, a, b)` означает «x, но не меньше a и не больше b».

   ```
   всего   = balance (текущий счёт)
   deposit = clamp(вклад, 0, всего)                 — только если вклад сейчас не открыт, иначе 0
   must    = clamp(обязательные, 0, всего − deposit)
   want    = clamp(необязательные, 0, всего − deposit − must)
   срок    = clamp(срок, MIN_TERM_DAYS, MAX_TERM_DAYS)
   сбережения (plannedSavings) = всего − must − want − deposit      (Budget.savingsOf)
   ```

3. **Подтверждение** (`confirmBudget`): если выбран вклад — открывается вклад, `balance −= deposit`,
   строка журнала «Вклад открыт»; создаётся `BudgetState(plannedMust, plannedWant, plannedSavings,
   plannedDeposit, spentMust = 0, spentWant = 0, startDay)`. План до следующего бонуса не меняется.
   Если подтверждённого бюджета нет вовсе (первый запуск), планировать можно сразу
   (`GameUiState.canPlanBudget`).
4. **Покупки** увеличивают факт по видам (`buyCart`):

   ```
   spentMust += Σ стоимость еды и игрушек            (SpendKind.MUST)
   spentWant += Σ стоимость одежды, декора, «Другого» (SpendKind.WANT)
   перерасход(вид) = max(0, spent(вид) + корзина(вид) − planned(вид))   — Budget.overspendOf
   ```

   Перерасход — предупреждение в окне подтверждения покупки «Обязательные: +N сверх плана» /
   «Необязательные: +N сверх плана», покупку он не запрещает. Запрещает только нехватка денег: `стоимость корзины ≤ balance`.
5. **Итог периода** (при следующем бонусе дня) — `BudgetResult`:

   ```
   actualMust = spentMust,  actualWant = spentWant
   actualSavings = balance до начисления нового бонуса
   разница: обязательные = planned − actual; необязательные = planned − actual;
            сбережения = actual − planned
   (плюс — уложились или сберегли больше, минус — вышли за план)
   ```

   Итог показывается при планировании следующего периода и попадает в историю (`BudgetHistory`,
   видна взрослому во вкладке «Дни»).

В план **не** входят: деньги квестов, ручные изменения взрослым, открытие и возврат вклада.

Шаг кнопок «−/+» — «круглое» число около десятой доли суммы: 1, 5, 10, 25, 50, 100, 250, 500…
(`amountStepOf`); сдвиг идёт от круглого значения (37 + шаг 10 = 40).

## 5. Вклад

`Deposit(amount, termDays, ratePercent, openedDay)`:

Ставка в процентах за весь срок зависит от срока: чем длиннее срок, тем выше ставка. Таблица
ставок (`Deposit.RATES`, читается через `Deposit.rateOf`) — единственный источник правды, в
документации она не дублируется.

```
проценты       = round(сумма × ставка / 100)                (Deposit.interestOf)
день погашения = день открытия + срок                       (maturityDay, календарные дни)
в день погашения и позже:  balance += сумма + проценты      — строки «Вклад закрыт» и «Проценты по вкладу»
                                                            (строки процентов нет, если они 0)
досрочное закрытие:        balance += сумма                 — строка «Вклад закрыт досрочно», проценты не начисляются
```

Открыть вклад можно только при планировании периода и только если другой вклад не открыт.
Созревший вклад гасится автоматически: при создании модели, при переходах между экранами, в каждом
`tick()`, после перемотки, перед раскладкой и подтверждением (`settleMaturedDeposit`). Перед
досрочным закрытием экран предупреждает «Проценты сгорят».

Пример: вклад на срок в N дней вернёт сумму плюс проценты по ставке этого срока через N
календарных дней.

## 6. Журнал

`MoneyEntry(reason, delta, gameDay, timestampMillis, …)` — каждое изменение текущего счёта, новые
сверху, до 500 записей (`MoneyLog`). Экран «Журнал» группирует записи по дням и показывает баланс и
сумму на вкладе.

| Причина | Когда |
|---|---|
| «Бонус дня» | `claimDailyBonus` |
| «<товар> xN» | покупка, по строке на позицию (с `itemId`, вариантом, количеством, видом траты) |
| «Вклад открыт» / «Вклад закрыт» / «Проценты по вкладу» / «Вклад закрыт досрочно» | вклад |
| «Квест: <название>» | вариант квеста с деньгами |
| «Взрослый добавил 50: за уборку» / «Взрослый убрал 20: …» | ручное изменение взрослым (`MoneyEntry.fromAdult`) |
| «Награда» | `GameViewModel.earn` с причиной по умолчанию |

## 7. Ручное изменение монет взрослым

Взрослый режим → вкладка «Журнал» → «Изменить монеты» (`AdultMoney`, `adjustBalanceByAdult`):

```
«Добавить»: balance += сумма
«Убрать»:   balance −= сумма, только если сумма ≤ balance (ниже нуля нельзя)
сумма 1–999 (AMOUNT_MAX), причина обязательна, до 60 символов (REASON_MAX)
```

Вклад и план периода не меняются; запись видна и ребёнку в журнале.

## 8. Цели

Цель — товар в варианте, отмеченный звёздочкой в магазине; прогресс = `balance / цена` (0–1), цена —
с учётом наценки. Подробно — [items.md](items.md), раздел 7.
