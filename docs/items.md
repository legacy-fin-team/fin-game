# Предметы, магазин и инвентарь

Как устроены предметы: категории, использование, экипировка одежды и декора, пути к спрайтам,
магазин, цены, цели и свои предметы взрослого. В конце — пошаговый пример добавления нового
предмета.

Пути к исходникам даны относительно `app/src/main/java/com/legacy/fingame/`, пути к данным —
относительно `app/src/main/assets/`.

Связанные разделы: [игровая область и слои](scene.md), [животные и этапы роста](animals.md),
[рост питомца и наценки](pet-growth.md), [экономика и бюджет](economy.md).

## 1. Модель

| Класс | Файл | Что это |
|---|---|---|
| `Item` | `game/items/Item.kt` | Товар: `id`, `name`, `price`, `category`, `variantIds`, `declaredEffects`, `layer`, `iconOverride` |
| `ItemCategory` | `game/items/ItemCategory.kt` | Раздел магазина; задаёт способ использования, слой по умолчанию и вид траты |
| `ItemUse` | `game/items/ItemUse.kt` | Что происходит с предметом при использовании |
| `ItemSelection` | `game/items/ItemSelection.kt` | Товар + вариант — то, что покупают, хранят и надевают |
| `ItemSprites` | `game/items/ItemSprites.kt` | Единственное место, где строятся пути к спрайтам предметов |
| `ItemReader`, `ItemRegistry` | `game/items/ItemReader.kt`, `ItemRegistry.kt` | Чтение `assets/data/items.xml` при старте |
| `ItemCatalog` | `game/items/ItemCatalog.kt` | Интерфейс каталога: `getItemsByCategory`, `findItemById` |
| `CompositeItemCatalog` | `game/items/CustomItems.kt` | Каталог игры + свои предметы взрослого (`GameViewModel.catalog`) |
| `CarePricedCatalog` | `game/rules/CarePricedCatalog.kt` | Тот же каталог с ценами после наценки (`GameViewModel.shopCatalog`) |
| `Cart`, `CartLine` | `game/items/Cart.kt` | Строки корзины, траты по видам |
| `Inventory`, `InventoryEntry` | `game/items/Inventory.kt` | Строки инвентаря |
| `Goals`, `GoalLine` | `game/items/Goals.kt` | Цели (звёздочка в магазине) |

## 2. Категории

| Категория | `xmlName` | Использование (`ItemUse`) | Слой сцены по умолчанию | Вид траты (`SpendKind`) | Кнопка в инвентаре |
|---|---|---|---|---|---|
| Еда | `food` | `CONSUMED` — съедается, −1 шт. | — | `MUST`, «Обязательные» | «Съесть» |
| Игрушки | `toys` | `REUSABLE` — остаётся в инвентаре | — | `MUST` | «Поиграть» |
| Одежда | `clothes` | `WEARABLE` — надевается и снимается | `CLOTHES` | `WANT`, «Необязательные» | «Надеть» / «Снять», состояние «Надето» |
| Декор | `decor` | `WEARABLE` — ставится в комнату и убирается | `ENVIRONMENT_BACK` | `WANT` | «Поставить» / «Убрать», состояние «Стоит» |
| Другое | `other` | `REDEEMED` — награда из жизни, используется один раз | — | `WANT` | «Использовать» |

Подписи для одежды и декора даёт сама категория: `ItemCategory.wearActionTitle(worn)` и
`ItemCategory.wornStateTitle()`.

Правила:

- `Item.isWearable` — `use == WEARABLE` и у предмета есть слой;
- `Item.effects` пуст у всего, что надевается: одежда и декор шкалы не меняют, даже если в XML у них
  указан `<effect>` (он читается в `declaredEffects` и игнорируется); эффектов нет и у наград
  «Другое»;
- у одного предмета одновременно надет только один вариант: надевая один вариант одежды, игрок снимает
  другой вариант той же вещи (`GameViewModel.toggleWorn`);
- раздел «Другое» в магазине виден, только когда в нём есть предметы (их добавляет взрослый):
  фильтр в `ui/FinGameApp.kt`.

## 3. Каталог `items.xml`

Формат записи (сначала одежда с несколькими вариантами и без эффектов, затем еда с одним вариантом
и эффектами на шкалы; `…` — значение, которое выбирает автор):

```xml
<item id="some-clothes" name="Название" price="…" category="clothes">
    <variants>
        <variant id="first" />
        <variant id="second" />
    </variants>
</item>
<item id="some-food" name="Название" price="…" category="food">
    <variants>
        <variant id="default" />
    </variants>
    <effects>
        <effect stat="hunger" value="…" />
        <effect stat="health" value="…" />
    </effects>
</item>
```

| Атрибут / тег | Обязателен | Смысл |
|---|---|---|
| `id` | да | Имя папки спрайтов предмета; должен быть уникальным во всём каталоге |
| `name` | нет | Название для игрока; если пусто — показывается `id` |
| `price` | да | Цена в монетах, одинаковая для всех вариантов |
| `category` | да | `food`, `toys`, `clothes`, `decor`, `other` |
| `layer` | нет | Слой сцены, если отличается от слоя категории: `background`, `environment-back`, `animal`, `environment-front`, `clothes` (см. [scene.md](scene.md)) |
| `<variants>/<variant id>` | да, хотя бы один | Варианты (окрасы); первый — вариант по умолчанию |
| `<effects>/<effect stat value>` | нет | Эффект на шкалы `health`, `hunger`, `pleasure`, со знаком |

`ItemReader` пропускает запись с ошибкой (нет `id`, неизвестная категория, нет цены, нет вариантов,
повтор `id` в категории) с сообщением в logcat и продолжает читать остальные. Неизвестный слой
заменяется слоем категории, неверный эффект отбрасывается.

Состав каталога (какие товары есть, их цены, варианты и эффекты) не фиксируется в этой
документации: он меняется вместе с балансом. Источник правды — `assets/data/items.xml`. По
смыслу каталог устроен так:

- **обязательные** товары — категории «Еда» и «Игрушки» (вид траты `MUST`): то, что нужно для ухода
  за питомцем;
- **необязательные** товары — «Одежда» и «Декор» (вид траты `WANT`): украшения, на шкалы они не
  влияют;
- еда восстанавливает голод и здоровье, игрушки поднимают настроение; конкретные значения
  эффектов заданы в `<effects>` каждого товара;
- у одежды и части декора несколько вариантов (окрасов), у остальных один вариант `default`;
- у каждого варианта в `assets/textures/items/` есть свой спрайт.

Требования ТЗ к каталогу (не меньше 8 товаров двух типов, есть и обязательные, и необязательные)
проверяет тест по фактическим данным (`ItemReaderTest`), а не числа в этом файле.

## 4. Спрайты предметов

Все пути строит `ItemSprites` (относительно `assets/textures/`); у каждого варианта своя папка
`items/<id>/<вариант>/`:

| Файл | Размер | Для чего | Кто строит путь |
|---|---|---|---|
| `icon.webp` | 32×32 | Иконка в магазине, инвентаре, корзине, целях | `ItemSprites.icon`, `Item.getIconPath` |
| `equipped-<animal>-<stage>.webp` | 32×32 | Одежда на питомце: для каждого вида животного и этапа роста своя картинка | `ItemSprites.equippedOnAnimal`, `Item.getEquippedSpritePath` |
| `placed.webp` | 128×128 | Декор в комнате: одна картинка на вариант, без привязки к животному | `ItemSprites.placedInScenery` |

Полный путь одежды: `/assets/textures/items/<id>/<variant>/equipped-<animal>-<stage>.webp`,
например `items/<id>/<вариант>/equipped-cat-1.webp`, где `<animal>` — `id` животного из
`animals.xml`, а `<stage>` — этап роста, **уже ограниченный** числом нарисованных стадий животного:
`animalRegistry.coerceAge(pet.animalId, state.petAge)` (`Animal.coerceAge`, вызов в
`ui/FinGameApp.kt`). Питомец продолжает «расти» после последнего нарисованного этапа
(`Growth.ageOf` не ограничен), но одежда не запрашивает несуществующий этап — см.
[pet-growth.md](pet-growth.md).

Какой спрайт брать, решает слой предмета (`Item.getEquippedSpritePath`):

- слой `CLOTHES` — `equipped-…`; без питомца одежду не рисуют;
- любой другой слой (`ENVIRONMENT_BACK`, `ENVIRONMENT_FRONT` и т. д.) — `placed.webp`;
- нет слоя (еда, игрушки, «Другое») — ничего не рисуется на сцене.

Вариант, которого больше нет в данных (например, сохранённый до изменения XML), заменяется
вариантом по умолчанию. Отсутствующий файл не ломает игру: `SpriteLoader` рисует вместо него
`textures/error/error.webp` и пишет в logcat.

У своих предметов взрослого нет папки в `items/`: иконка выбирается из готовых спрайтов игры
(`CustomItemIcons.ALL`) и хранится в `Item.iconOverride`.

## 5. Магазин

Экран `ui/screens/ShopScreen.kt`, данные — `GameViewModel.shopCatalog`.

- Разделы: категории по порядку `ItemCategory`; «Другое» — только если не пусто.
- Карточка: иконка выбранного варианта, цена (с наценкой, если есть серия дней без заботы, см.
  [pet-growth.md](pet-growth.md)), эффекты, выбор варианта (`pickVariant`), звёздочка «цель»
  (`toggleGoal`).
- Корзина: `quantities` (по `id`) и `pickedVariants`; сбрасывается при уходе с экрана магазина.
  Предел количества (`GameViewModel.maxQuantityOf`): еда — до 99 (`MAX_ITEM_QUANTITY`); остальное —
  1 шт. (`SINGLE_ITEM_QUANTITY`), и 0, если этот вариант уже куплен.
- Кнопка «Купить · N» открывает окно подтверждения «Покупка»: состав корзины, «Итого»,
  «Останется» и предупреждение о перерасходе плана, например «Необязательные: +N сверх плана»
  (`Budget.overspendsOf`, `overspendTextOf`) — это предупреждение, а не запрет (см.
  [economy.md](economy.md)).
- Нехватка денег: окно «Не хватает монет» и «Ещё нужно N» (`GameUiState.cartShortfall`).
- Покупка («Купить» в окне, `GameViewModel.buyCart`): стоимость пересчитывается по текущим ценам; с баланса
  списывается сумма, в инвентарь добавляются предметы, в журнал — строка «<товар> xN» на каждую
  позицию, в бюджет периода — траты по видам `MUST`/`WANT`; купленные цели снимаются; игрок
  возвращается на главный экран.

## 6. Инвентарь

Экран `ui/screens/InventoryScreen.kt`, строки — `Inventory.entriesOf` (сортировка: категория,
название, вариант).

- Еда: `useItem` — эффекты на шкалы, −1 шт.
- Игрушка: `useItem` — эффекты на шкалы, остаётся.
- Одежда и декор: `toggleWorn` — надеть/снять или поставить/убрать; шкалы не меняются.
- «Другое»: `useItem` — предмет исчезает, в журнал использованных наград (`RewardUsageLog`)
  пишется что, кто (имя питомца) и когда; это видит взрослый во вкладке «Награды».

Использование предмета поднимает лучший индекс ухода за день (`PetCare.noticed`), от которого зависит
рост питомца.

## 7. Цели

Звёздочка на карточке магазина делает выбранный вариант целью (`toggleGoal`). Цели видны в карусели
на главном экране (`GoalsCarousel`) с прогрессом накопления:

```
прогресс = 1,           если цена ≤ 0 или balance ≥ цена
         = 0,           если balance ≤ 0
         = balance / цена  иначе                         (game/economy/GoalProgress.kt)
```

Целью может быть товар из каталога в существующем варианте, который ещё не куплен (еда — всегда).
Купленная цель снимается сама, счётчик `goalsReached` растёт (признак темы «Цели» в разделе
«Прогресс» взрослого, см. [education.md](education.md)).

## 8. Свои предметы взрослого

Во взрослом режиме, вкладка «Товары» (`ui/screens/AdultItemsTab.kt`), взрослый добавляет свои
предметы (`GameViewModel.addCustomItem`, `removeCustomItem`). Правила — `CustomItems`:

| Правило | Значение |
|---|---|
| Число своих предметов | не больше 50 (`MAX`) |
| Название | до 20 символов (`NAME_MAX`) |
| Цена | 1–999 (`PRICE_MIN`, `PRICE_MAX`) |
| Эффекты | −50…+50 с шагом 5 (`EFFECT_MIN`, `EFFECT_MAX`, `EFFECT_STEP`), только у еды и игрушек |
| Разделы | еда, игрушки, одежда, декор, «Другое» (`CATEGORIES`) |
| `id` | `custom-<момент>` (`ID_PREFIX`), один вариант `default` |
| Иконка | одна из готовых иконок игры (`CustomItemIcons.ALL`) |

Свои предметы продаются наравне с предметами игры (в конце каждого раздела), на них тоже действует
наценка. Одежду и декор взрослого можно надеть или поставить, но нарисованного вида на питомце или
в комнате у них нет (папки `items/<id>/` нет), поэтому на сцене вместо них рисуется заглушка
`error.webp`. Раздел «Другое» задуман именно для наград из жизни («поход в кино»).
Сброс прогресса свои предметы взрослого не удаляет.

## 9. Пример: как добавить новый предмет

Добавим одежду (`new-clothes`) в двух вариантах и еду (`new-food`). Названия, цены и эффекты
ниже — условные, реальные значения выбирает автор предмета.

1. **Данные.** В `app/src/main/assets/data/items.xml`:

   ```xml
   <item id="new-clothes" name="Название" price="…" category="clothes">
       <variants>
           <variant id="first" />
           <variant id="second" />
       </variants>
   </item>
   <item id="new-food" name="Название" price="…" category="food">
       <variants>
           <variant id="default" />
       </variants>
       <effects>
           <effect stat="hunger" value="…" />
           <effect stat="health" value="…" />
       </effects>
   </item>
   ```

   У одежды и декора эффектов не указывают — тест из шага 3 это проверяет. Декору, который должен
   стоять перед питомцем, можно задать `layer="environment-front"`.

2. **Текстуры** (WebP, пиксельная графика) в `app/src/main/assets/textures/items/`:

   ```
   items/new-food/default/icon.webp                  32×32 — еда: только иконка
   items/new-clothes/first/icon.webp                 32×32
   items/new-clothes/first/equipped-<animal>-<stage>.webp
                                                     32×32 — по картинке на каждое животное
                                                     и каждый этап роста из animals.xml
   items/new-clothes/second/…                        то же для второго варианта
   ```

   Для декора вместо `equipped-…` кладётся один `placed.webp` 128×128 на вариант. Спрайт одежды
   рисуется поверх питомца в сетке 32×32 его собственного спрайта (см. [scene.md](scene.md)).
   Если чужая текстура (не нарисованная командой) — добавить её в `attributions.xml` рядом (см.
   «Лицензии» в [README](../README.md#лицензии)).

3. **Тест.** В `app/src/test/java/com/legacy/fingame/ItemReaderTest.kt` уже есть проверки
   поставляемого каталога (`the data the app ships with …`): каждый предмет читается, путь иконки
   каждого варианта строится как `items/<id>/<вариант>/icon.webp`, у одежды и декора нет эффектов.
   Тест сверяет только строку пути — **отсутствие текстур тесты не ловят**: пропущенный файл
   видно только в игре (заглушка `error.webp`) и в logcat (`SpriteLoader`). Для новой еды стоит
   дописать ожидаемые эффекты по образцу уже имеющихся в этом тесте.

4. **Проверка.** `./gradlew :app:testDebugUnitTest`, затем в игре: магазин → нужный раздел
   (выбор варианта), покупка, инвентарь → «Надеть» — вещь на питомце; перемотать время до
   следующего этапа (демо-сборка, «+12 ч» много раз с кормлением питомца: этап занимает `Growth.STAGE_MILLIS` роста, то есть несколько дней) — картинка сменилась на `equipped-<animal>-1`.

Код менять не нужно: каталог, магазин, инвентарь, сцена и сохранение работают с любым предметом из
XML.
